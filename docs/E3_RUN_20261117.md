## Máy và định nghĩa đo

Intel i5-11400H,12CPU logic, WSL RAM khoảng5,65GiB; Python3.12.3;
ClickHouse26.10.3.7. Môi trường đầy đủ được lưu trong ZIP và windows_environment.json.
K1(CounterID,EventDate),g8192,Wide,LZ4,fsync_after_insert1,async_insert0,insert1thread.

ACK elapsed đo first HTTP send→last complete response, gồm xử lý input/journal giữa batch.
Không tính tải/chuyển nguồn, chuẩn bị bảng hay thời gian producer gom batch.
Snapshots gần sauACK có độ trễ hoàn thành0,0073–0,1444s; không phải snapshot nguyên tử.
Merge log lọc theo table_uuid đến mốc server observation_end sau snapshot ổn định.
Tổng merge duration không phải wall/CPU time. Merge row amplification là proxy đọc lại,
không phải physical SSD write amplification. Active bytes không gồm mọi inactive/tạm.

## Tái lập

1. Dùng code tại commit đã ghi, cài đúng ClickHouse; cấu hình credential riêng ngoài repo.
2. Chuẩn bị nguồn và mẫu bằng dataset, kiểm lock `manifests/hits30m.e3.lock.json`;
   chạy audit_e3_sources.py. Hash không khớp thì không âm thầm thay lock hay dùng khác thứ tự.
3. Dùng `study.py --protocol configs/protocol.e3.v2.json init ...` với run ID mới.
4. Chạy ingest1m ở run pilot riêng, summarize và e3_check_results.py để xác minh.
5. Chạy init/ingest30m/summarize/check/plot/package ở run chính mới.
   e3_check_results.py dùng nhãn membertai/machinewsl_i5; đổi nhãn thì điều chỉnh helper cho phù hợp.
6. Không ghi đè hoặc retry INSERT mơ hồ; giữ nguyên mọi số đo, lỗi và hồ sơ run chưa hoàn tất.

Các bảng runtime vẫn được giữ để kiểm tra, nhưng background merge tương lai có thể đổi
parts/storage. Dùng snapshots đã lưu khi trích kết quả của run17/11/2026.
